# ViT 逐算子误差与前缀替换

仅比较ViT输出，使用同C7权重的严格PyTorch FP32参考。诊断在独立源码副本中完成，局部FP32前缀不是正式运行方案。正常配置默认FP16；需要整体FP32中间张量时使用`--vision-dtype fp32`，NPU GEMM仍为FP16。

## 误差产生与放大

红图最后一层输入相对L2为1.0614%。对这个实际输入使用FP32执行最后一层，输出相对参考仍为2.6918%，实际NPU结果为2.6959%；相同输入下该层自身数值偏移为0.0502%。每层重新从舍入后的gold输入开始时，末层输出偏移只有0.0468%。因此末层主要放大继承误差，不能从累积曲线的末层跳变推断主要误差源在末层。

同输入首层局部误差：norm/residual通常约0.02%，up约0.024%，down约0.037%–0.038%，Attention约0.063%–0.072%。这些小差异经过后续计算后对最终features的影响不同；局部误差范数不能直接相加。

`summary.json`中的prefix_replacement以“已经记录的NPU前缀＋后续FP32图”逐段替换。相邻结果的差向量投影到最终误差方向，所有带符号投影之和为1。paired-prefix-summary.json对新旧两条NPU轨迹执行相同操作，入口及前两个block的投影合计为红图88.69%、蓝图71.20%。该归因依赖替换顺序，可有负值，不是唯一的方差分摊，也不保证真实NPU后续替换的改善幅度。

首层实际中间值的细分中，残差回写、MLP结果及相关norm边界较突出，GELU与RoPE本身未表现为主要来源。Attention内部的FP16边界模拟未逐位复现实际NPU，细分仅作敏感度对照，不把其残差强行归到指数近似或某个MAC环节。

PyTorch普通FP16对照在同三档输入上的偏移为2.5080%/0.9556%/1.8887%，并不低于当前NPU FP16。早期敏感性是定位结果，不构成采用特殊FP32前缀配置的理由。
